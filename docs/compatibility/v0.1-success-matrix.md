# v0.1 Success-Criteria Matrix

Date: 2026-08-14.

This matrix maps the sixteen section 26 MVP success criteria to committed evidence. It is the
pre-release audit for issue `#102`; the release-only rows become final only after the v0.1.0
publish workflow and post-publish smoke complete.

| # | Criterion | Evidence | Status |
|---:|---|---|---|
| 1 | Install without Python, Docker, a compiler toolchain or a model download | CI `clean install` runs `pnpm install --ignore-scripts`, `pnpm check:no-native`, `lore doctor --ci`, and a build/search smoke on macOS, Ubuntu and Windows; manual clean-machine scenario in [`docs/testing/acceptance.md`](../testing/acceptance.md). | release-time smoke pending |
| 2 | Run `lore dev ./artifacts` and receive a verified active build | Acceptance `dev/starts-from-unconfigured-folder` and Studio e2e run against the real `lore dev`. | satisfied in CI |
| 3 | Inspect exactly what was parsed and excluded | Acceptance and CLI tests cover `lore inspect sources`, warnings, source reads and binary exclusions. | satisfied in CI |
| 4 | Connect Claude Code, Codex or VS Code through one safe command with no global mutation by default | Integration docs record client-specific verification and trust prompts: [`claude-code.md`](../integrations/claude-code.md), [`codex.md`](../integrations/codex.md), [`vscode.md`](../integrations/vscode.md). | manual trust-prompt refresh pending |
| 5 | Let an agent launch against a source-checked active build and retrieve task-specific context without scanning every artifact | MCP and runtime contract tests cover `lore_context_for_task`; performance evidence is in [`performance-v0.1.md`](performance-v0.1.md). | satisfied in CI |
| 6 | Create a 24k-budget context export for a web chat | Acceptance and CLI export tests cover bounded export and omissions. | satisfied in CI |
| 7 | Query CSV/XLSX-derived tables without flattening them into prose | Mixed-artifact acceptance and table-query tests cover typed table catalog and SQL query paths. | satisfied in CI |
| 8 | Trace every result to a document section, page, sheet, cell range or line range | Runtime, search, context-bundle and table tests assert `SourceLocator` presence; acceptance covers search JSON locators. | satisfied in CI |
| 9 | Declare an active source, archive old material and mark supersession deterministically | Rule semantics tests and no-conflict-claims check cover user-declared `authority`, `status` and `supersedes`. | satisfied in CI |
| 10 | Edit, add or delete artifacts and rebuild only affected outputs | Lifecycle acceptance, watch tests and benchmark evidence cover changed-file reuse. | satisfied in CI |
| 11 | See a human-readable plan and build diff | Acceptance covers `lore plan` and `lore diff`, including rollback diff behaviour. | satisfied in CI |
| 12 | Activate and roll back locally without recompilation | Lifecycle acceptance `rollback-without-reindexing` empties sources before rollback and still searches the restored build. | satisfied in CI |
| 13 | Deploy the exact build to Cloudflare through one command | Cloudflare acceptance provisions the target and deploys the built project. | satisfied in CI |
| 14 | Verify and activate the remote candidate atomically | Cloudflare acceptance verifies remote MCP search and rollback through the active pointer. | satisfied in CI |
| 15 | Use the full local workflow without an account or hosted service | Local acceptance, clean install and demo checks run without service credentials; Cloudflare is separate projection evidence. | release-time clean-machine smoke pending |
| 16 | Obtain the same build ID on supported operating systems from the same canonical inputs | Determinism tests run in the cross-platform `verify` matrix; Windows path tests cover platform-specific path handling. | satisfied in CI |
