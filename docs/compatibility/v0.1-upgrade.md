# v0.1 upgrade notes

These notes apply to the first stable Lorepack release and to projects created by the
`@lorepack/cli` package.

## Package compatibility

The public npm package for v0.1 is `@lorepack/cli`. The packages under `packages/` are private
workspace implementation packages and are bundled into the CLI. Install or upgrade the public
package with:

```bash
pnpm add -g @lorepack/cli@latest
# or
npm install --global @lorepack/cli@latest
```

The CLI version identifies the command and runtime implementation. It does not change the
identity of an existing build. Keep a copy of the CLI version used to produce a build when a
reproducible rebuild matters.

## Build and archive compatibility

Lorepack records two compatibility values:

- `formatVersion` is the `.lorepack` archive contract. A reader must reject an unsupported
  archive format instead of guessing.
- `schemaVersion` is the sealed build catalog schema. A reader may open an older schema only when
  that schema is explicitly supported by the installed CLI.

Rebuild from the source directory when upgrading across a format or schema boundary. Do not copy
the SQLite files from `.lore/` into a new project and do not treat a successful file copy as a
migration.

## Safe upgrade procedure

1. Record the current CLI version with `lorepack --version`.
2. Commit or archive the source files and `lore.yaml` used to produce the active build.
3. Install the target CLI version.
4. Run `lorepack doctor --json`, then `lorepack plan` to inspect the intended rebuild.
5. Run `lorepack build` and validate the new build before activation or deployment.
6. Compare the new build with the active build using `lorepack diff`.
7. Activate or deploy only after the diff and capability report are expected.

The old immutable build remains available for rollback. A rollback changes the active pointer; it
does not recompile source files.

## Cloudflare targets

Cloudflare targets created for v0.1 use separate catalog and table-data D1 databases. A receipt
created before that boundary is intentionally rejected during deploy. Run
`lorepack target add cloudflare` again, review the resource plan, and migrate the target before
deploying with the new CLI.

## Release history

See the package changelogs in the GitHub release for the exact changes in each published version.
The release workflow generates those changelogs from Changesets and includes them in the release
